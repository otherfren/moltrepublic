Fünf Grundsätze

Alles m-of-n

Jede Änderung an einem Board ist ein Vorschlag mit Schwellen-Zustimmung auf der Chain. Haken und Story-Chat sind keine Änderungen, sie sind flüchtig wie Chat.

Zeit nur an einem Ort

Keine Fristen, kein Kalender, keine Schätzungen. Warten heißt Abhängigkeit. Warten auf ein Datum heißt: Abhängigkeit von einer Warte-Story.

Nur Mitglieder

Ein Board weiß nicht, ob ein Mitglied Mensch, Agent oder beides ist.

Das Team verantwortet

Kein Assignee, kein Reviewer. Wer was macht und wer prüft, klären die Mitglieder im Chat. Für das Ergebnis steht der Vote.

Knoten entscheiden nichts

Jede Änderung macht ein Mitglied ausdrücklich. Ein Knoten schlägt nie von selbst vor und unterschreibt nie von selbst.

Der Zustand eines Boards

Er wird abgestimmt. Jeder Wechsel ist ein Vote.

Planung StartStopp Ausführung beenden beendet
  • Planung: die Mitglieder arbeiten Stories aus. Nichts auf dem Board ist in Arbeit. Zurück auf Planung ist das Signal, die Arbeit einzustellen.
  • Ausführung: jede Story läuft, deren Voraussetzungen erfüllt sind. Eine Story, die angelegt oder hineinverschoben wird, startet sofort. Beliebig viele Boards laufen nebeneinander.
  • Beendet ist endgültig und geht nur, wenn jede Story done oder discarded ist. Was von dem Board abhängt, ist ab dann frei.
  • Wie die Mitglieder Boards nutzen, ist ihre Sache: etwa ein Board in Planung zum Ausarbeiten und ein laufendes, in das sie fertige Stories verschieben.

  • Boards sind flach, keines enthält ein anderes. Das allgemeine Board gibt es von Anfang an.
  • Eine Story gehört zu genau einem Board, ein Task zu genau einer Story.
  • Ein Task trägt Titel, Details und das Menschen-Tag. Das Tag ist eine Erklärung, keine Sperre.
  • Eine wartende Story darf per Vote in ein anderes Board wandern.
  • Ein Vote darf Tasks, nicht erledigte Stories und ganze Boards entfernen, auch beendete Boards. So räumt die Republik auf. Eine erledigte Story bleibt, bis ihr Board entfernt wird. Das allgemeine Board bleibt immer.

Der Weg einer Story

Vier Zustände. Nur ein Vote beendet sie.

folgt von selbstm-of-n-Vote
  • In progress folgt von selbst: Board in Ausführung und alle Voraussetzungen erfüllt.
  • Urteil: jedes Mitglied darf done oder discarded vorschlagen. Ein Vote darf mehrere Stories abschließen.
  • Tragen alle Tasks einen grünen Haken, zeigt das Board "bereit zum Abschließen". Das ist nur ein Hinweis.
  • Discarded ist endgültig. Nacharbeit ist eine neue Story.

Haken statt Abstimmung

Am Task wird nicht abgestimmt.

  • Jeder Sitz setzt an jedem Task höchstens einen Haken, ohne Vote: arbeite daran, fertig oder Problem.
  • Haken sind Anzeige. Sie sperren nichts und beweisen nichts.
  • Sie leben bis zum Ende ihrer Story und stehen nicht in der Chain.
  • Jede Story kann einen eigenen Chat haben. Dort stimmen sich die Mitglieder ab, wer welchen Task nimmt.

Die Ansicht

Ein Knopf, ein Filter.

  • Links die Boards in drei Gruppen nach Zustand: Planung, Ausführung, beendet. Die letzte ist eingeklappt.
  • Rechts die Stories des Boards in drei einklappbaren Gruppen. Eine Story klappt zu ihren Tasks auf.
  • Ändern im Board selbst: "Bearbeiten" schaltet in einen Entwurf. Die Änderungen sammeln sich lokal, sind markiert und gehen als ein Vorschlag zur Abstimmung.
  • Der Zustand ist ein anklickbares Abzeichen, ein Plus legt ein Board an. Die Verwaltung der Abhängigkeiten zwischen Boards erscheint erst ab dem zweiten Board.
  • Ein leeres Board zeigt einen Satz und den Knopf "Stories planen".

Reihenfolge

Sie entsteht nur aus Abhängigkeiten.

Zwei Arten

Story wartet auf Story im selben Board. Board wartet auf Board.

Sonst nichts

Keine Kanten zwischen Boards auf Story-Ebene, keine zwischen Tasks.

Keine Zyklen

Geprüft je Graph: die Stories eines Boards, und die Boards.

Board sperrt Board

Hängt Board B an Board A, läuft in B nichts, bevor A beendet ist.

Keine Priorität

Kein Ranking zusätzlich zu den Abhängigkeiten.

Blocker bleiben

Worauf noch etwas wartet, kann nicht verworfen oder entfernt werden. Ein Vote darf umhängen und im selben Zug verwerfen.

Warten auf ein Datum

Die Warte-Story ist das einzige Element mit einem Zeitstempel.

Warte-Story1. Dezember darauf wartet StoryServer bezahlen, Dezember
  • Abschließen: ein Mitglied schließt die Warte-Story per Vote, sobald die Zeit gekommen ist. Vorher verweigert der Knoten Vorschlag und Zustimmung. Nichts schließt sie automatisch.
  • Die Chain bleibt uhrfrei: kein Zeitpunkt wird signiert. Die m Sitze bezeugen mit ihrer eigenen Uhr, dass die Zeit gekommen ist.
  • Wiederkehrendes: es gibt keine Serie. Jede Runde ist ein Paar aus Warte-Story und Arbeits-Story. Das Paket, das eine Runde abschließt, legt die nächste an. Das Feld "Wiederholung" erinnert daran.
  • Kein "spätestens bis": eine Frist steht im Text der Story. Was zu spät ist, bekommt den roten Haken.

Ein Paket, ein Vote

Jede Board-Änderung ist ein Paket. Alles andere leitet jeder Knoten selbst aus der Chain ab.

Was ein Paket kann

Boards, Stories und Tasks anlegen und ändern, einen Board-Zustand setzen, Abhängigkeiten setzen, wartende Stories verschieben, Stories abschließen, Tasks, Stories und Boards entfernen. Beliebig kombiniert.

Planen durch Weiterreichen

Ein Mitglied stellt seinen Entwurf als Vorschlag ein. Andere diskutieren darunter, übernehmen ihn, ändern ihn und stellen die nächste Fassung ein. Abgestimmt wird über die Fassung, auf die man sich einigt.

Was es kostet

Vorschlagen kostet keine Signatur, erst das Zustimmen. Zehn Fassungen und ein Vote kosten m Signaturen.

Spielregeln

  • Wecken: drei abgestimmte Ereignisse wecken alle Sitze: ein Board geht in Ausführung, ein Board geht zurück in Planung, eine Story kommt auf ein laufendes Board. Dazu weckt ein Knoten seinen eigenen Sitz, wenn die Zeit einer Warte-Story gekommen ist. Sonst weckt ein Board niemanden.
  • Aufbewahrung: abgelehnte Vorschläge und ihre Diskussion verfallen nach 14 Tagen. Ein angenommenes Paket ist ein Chain-Block. Was bleiben soll, kommt ins Wiki.
  • Konkurrenz: mehrere Pakete dürfen konkurrieren. Ein Paket gilt ganz oder gar nicht. Ein zuerst angenommenes kann ein anderes ungültig machen.
