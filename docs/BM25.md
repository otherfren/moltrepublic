# Hybrid wiki search: BM25F + multilingual embeddings

**Status: PLAN, approved, scheduled after Robo-Scrum
(`docs/robo_scrum_plan.md`); decisions D1-D8 by the user 2026-11-24.**
Better word search in the wiki for everyone. A per-seat switch adds
search tools for agents, and meaning search from a model file the
operator brings, if a measured gate says so.

BM25 is a LEXICAL ranking function. Embeddings are not part of BM25;
they are a second retrieval method, combined with it in "hybrid" search.
The file keeps the name the user asked for.

## 0. Decisions (user, 2026-11-24)

| # | decision |
|---|---|
| D1 | nothing is ever downloaded by the product |
| D2 | a personal, per-seat setting, clearly visible in Settings |
| D3 | other seats are never affected |
| D4 | only the wiki is searched; Robo-Scrum is not |
| D5 | no model ships with the release |
| D6 | Settings explain in plain language what a model is, which ones work, where to get them, how to activate one |
| D7 | the switch is OFF by default |
| D8 | the better word search is always on for every existing wiki search; the switch governs only the new agent tools and, with a model, meaning search |

Recommended, accepted by default 2026-11-24:
- results need not be identical across seats;
- no further languages now;
- no C/C++ runtime, even as an opt-in;
- the user decides at the gate, with the numbers;
- pinned model hashes only;
- the embedding code goes in the default binary if the spike measures ≤ 5 MB and no C, else in a second release flavour.

## 2. Goals and non-goals

| goal | meaning here |
|---|---|
| BM25F | weighted fields (title 3, alias 3, header 2, tags 2, headings 1.5, body 1, relation text 1), per-field length normalisation, k1 1.2. tantivy has no native BM25F: field boosts in one `BooleanQuery` |
| German + English | per field a German and an English variant; n-grams on short fields (§3) |
| filters | type, tags, folder, props, relation; engine-side |
| sections | a hit is a header section with byte offsets of the matches (agent tools) |
| incremental | per applied patch |
| semantic (gated) | only from the operator's own model file (§4) |
| determinism | one seat: same index state, same order, ties by path |

Non-goals:
- boards, stories, tasks, file names, chat (D4);
- anything on the chain or the wire (D3);
- downloads (D1);
- a bundled model (D5);
- a reranker.

Results across seats may differ. tantivy keeps deleted documents in its
BM25 statistics until segments merge [INFERRED; verify in B2].

## 3. Lexical side: always on (D8)

| candidate | facts | verdict |
|---|---|---|
| tantivy (in tree, 0.26, MIT) | pure Rust with `lz4-compression` only; zstd off (guarded); 0.27 swaps its stemmer crate to `frostem` | TAKE |
| `bm25`, `fst` + own scoring | re-implements postings, phrases, snippets | LEAVE |
| SQLite FTS5 | C; sanctioned only in the opt-in `embedded-tor` build | LEAVE |
| `rust-stemmers` 1.2 (MIT/BSD-3) | Snowball de + en, pure Rust, no further deps (scratch `cargo tree`) | TAKE |
| `whatlang` 0.18 (MIT) | trigram language detection, pure Rust | TAKE |
| `lingua` 1.8 (Apache-2.0) | more accurate, per-language crates | LEAVE |
| `charabia` 0.10 (MIT) | `german-segmentation`; dictionary source, size and licence undocumented | SPIKE in B2: the body's compounds |
| character 3-4-grams | no dictionary; `Blockformat` -> `format` | TAKE on title, headings, alias and tags only: on the body they cost 3-5× the text [estimate] |

Fields:
- `<f>_de`: lowercase, ß -> ss, umlaut folding, German Snowball, stop words;
- `<f>_en`: English Snowball, stop words;
- `<f>_gram`: short fields only.

Query and page language:
- the query is analysed both ways;
- a section in language L weighs more on `<f>_L`.

**Always-on cost (every seat with the memory feature).**

| | today | upgraded [estimate, measured in B2] |
|---|---|---|
| index RAM | about the text size | about 2-2.5× the text: two analysed copies plus short-field n-grams |
| 2,000 pages × 2 KiB | about 4 MB | about 10 MB |
| 50,000 pages (spec scale) | about 100 MB | about 250 MB |
| first build | not measured | about 2-3× today's (two stemmers + detection), off the actor |
| per applied patch | delete + add + commit | the same, about 2× the analysis work |

B2's budget: ≤ 3× today's RAM and build time on the eval corpus, or the
n-gram field and the decompounder are cut back first.

There is no honest LEXICAL German<->English bridge.
- A curated term list is a hand-rolled thesaurus.
- No maintained pure-Rust bilingual dictionary crate was found.

Without a model, an English query finds English text and words both
languages share.

## 4. Semantic side: the operator's own model file

| option | verdict |
|---|---|

| (c) no embeddings | the fallback, and the state until a model is chosen |

| model | publisher, licence | languages | dims | `model.safetensors` | `tokenizer.json` |
|---|---|---|---|---|---|

| potion-multilingual-128M | Minish, MIT | 101 | 256 | 512.4 MB, sha256 `14b5eb39cb4ce5666da8ad1f3dc6be4346e9b2d601c073302fa0a31bf7943397` | 18.6 MB, sha256 `19f1909063da3cfe3bd83a782381f040dccea475f4816de11116444a73e1b6a1` |

Names, sizes and hashes were queried from the Hugging Face API on
2026-11-24 and MUST be re-verified against the real files before any
hash is pinned in code.

Sources (shown as text):
- `huggingface.co/minishlab/blink-multilingual-64M`
- `huggingface.co/minishlab/potion-multilingual-128M`

Cost with a model:
- disk is the files;
- RAM about the files' size while Meaning is on (f32 as loaded; quantising on load is a B5 question);
- vectors about 2 MB per 2,000 pages.

blink's card reports the highest MMTEB mean among the static models it
compares (51.60). There is no separate German number on it.

Why pinned hashes only (accepted):
- the gate measured those exact bytes;
- a wrong tokenizer gives silent garbage;
- a refusal can name what is wrong.

Runtimes (scratch `cargo tree`, outside the repo, deleted):

| runtime | facts | verdict |
|---|---|---|
| `model2vec-rs` 0.5.1 | defaults: `onig` (C) + `hf-hub` (downloads). With only `local-only`: 90 crates, no `cc`, no `-sys`; tokenising these vocabularies that way is unverified | TAKE for the B5 spike |
| `candle` 0.11 | pure Rust, 170 crates | fallback for a transformer model |
| `tract-onnx` 0.23 | pulls `cc` | LEAVE |
| `ort` / `fastembed` | C++ ONNX Runtime | LEAVE |

Vectors are a local RAM cache from the fold; chunks are header sections.
Brute-force cosine over 8,000 chunks is 2.0 M multiply-adds per query
[estimate: well under a millisecond]. Fusion is reciprocal rank fusion
(k = 60, ties by path), filters first.

## 5. Who gets what

| surface | switch OFF (default) | switch ON | ON + model ready + Meaning on |
|---|---|---|---|
| GUI wiki search bar | upgraded word search | upgraded word search | + meaning search (hybrid) |
| `wiki_search` on the seat key | upgraded word search, today's reply shape | + new options (modes, snippets with offsets, `why`, sections, `relation`, `lang`) | + `mode` semantic / hybrid |
| `wiki_search` on the read-only key | upgraded word search, today's reply shape | same as the seat key | same as the seat key |
| `wiki_read`, `wiki_read_many` (new) | refused: `agent search is off: [wiki] agent_search` | available on both keys | available |
| `wiki_models`, settings reads | seat key only, always | seat key only | seat key only |

With the switch off, the GUI bar and `wiki_search` on both keys run the
same upgraded word search over the same index and return the same hits
in today's reply shape. The new options and tools answer with the
refusal naming the key. So the GUI and MCP never differ in what they
find; agents only lack the richer reply.

The switch adds the agent tools on both keys. With a ready model and
Meaning on, meaning search reaches the GUI bar and `wiki_search` alike,
from the same index and vectors.

## 7. Agent surface and the D3 invariant

| item | content |
|---|---|
| `wiki_search` options (switch on) | `mode` lexical / semantic / hybrid (`no model on this seat` without one), `fields`, `relation`, `lang`; per hit `section` (heading path, byte range), `snippets` with `offsets`, `why` |
| `wiki_read`, `wiki_read_many` | sections by path and range, byte-capped |
| cursor | opaque over `(index_rev, offset)`, refused when the index moved |
| caps | reply ≤ 1 MiB (`MAX_RPC_LINE`, `molt-mcp/src/lib.rs:607`), ≤ 50 hits, snippet ≤ 300 chars |
| read key | gains only wiki reads; `MAX_CONNECTIONS` (64) and the log throttle bound cost |

Reply example (invented content):

```json
{"hits":[{"path":"a","title":"A","section":{"heading":["A","One"],"bytes":[120,480]},
  "score":7.1,"lang":"de","why":{"terms":{"title_de":["eins"]},"semantic_rank":2},
  "snippets":[{"field":"body","text":"... eins zwei ...","offsets":[[4,8]]}]}],
 "next_cursor":"r12:50","index_rev":12,"wiki_rev":12,"index_building":false}
```

**D3 invariant: no other seat can tell.**
- No new `WorkspaceEvent`, `ChainChange`, control frame or mirror-declaration field.
- No capability is announced.
- Nothing goes into the backup's shared parts or `status.seats[]`.
- No outbound request.

Pinned by:
- a test that toggles both switches, chooses a model folder and builds the index, asserting:
  - no envelope recorded;
  - `prefs.seat_caps` and the own mirror declaration unchanged;
  - no new file in the export;
  - the dialer called zero times;
- the existing wire-shape fixtures in `molt-core`, which stay green unchanged.

## 8. Evaluation and the gate

- Corpus: invented, in the repo: 60 pages (40 de, 20 en) and 50 queries (25 de, 25 en, 10 cross-language) with graded judgments.
- Metrics: recall@10, nDCG@10, MRR.
- Budgets, 4 cores / 16 GiB:
  - p95 ≤ 50 ms lexical, ≤ 150 ms hybrid;
  - build ≤ 10 s for 2,000 pages;
  - the always-on index ≤ 3× today's RAM.

| result | decision |
|---|---|
| hybrid with blink beats lexical by ≥ 0.10 nDCG@10 on cross-language AND ≥ 0.03 overall, within budget | (a): build the Meaning row |
| otherwise | (c): no Meaning row; the agent tools still ship |

The user decides at the gate with the numbers.
